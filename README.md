# نبض الطوارئ (نسخة Render)

خادم Node مع قاعدة بيانات Postgres. يرفع من GitHub إلى Render عبر ملف `render.yaml`.

## 1) GitHub
1. أنشئ مستودعاً جديداً (يفضّل أن يكون Private) باسم مثل `nabd`.
2. من `Add file` اختر `Upload files`، وارفع **كل ملفات هذا المجلد كما هي** بحيث تكون `server.js` و`render.yaml` و`index.html` في أعلى المستودع.
3. اضغط `Commit changes`.

## 2) Render
1. من لوحة التحكم: `New` ثم `Blueprint`.
2. اضغط `Connect` بجانب مستودع `nabd` (واربط حساب GitHub إن لم يكن مربوطاً).
3. اكتب اسماً للمخطط واختر الفرع `main`.
4. راجع القائمة: خدمة ويب `nabd-altawari` وقاعدة بيانات `nabd-db`.
5. اضغط `Deploy Blueprint` وانتظر انتهاء النشر.
6. افتح رابط الخدمة الذي ينتهي بـ `onrender.com`.

الربط بين الخدمة وقاعدة البيانات يتم تلقائياً عبر `DATABASE_URL` في `render.yaml`.
كل تعديل ترفعه على GitHub يُنشر تلقائياً.

## 3) أول تشغيل (افعله فور النشر)
تظهر شاشة «إعداد أول مرة». أنشئ حساب مدير النظام باسمك وكلمة مرور قوية.
تظهر هذه الشاشة مرة واحدة، ومن ينشئ الحساب الأول يصبح المدير.

## 4) تسجيل الموظفين واعتمادهم
- الموظف يفتح الرابط، يختار «حساب جديد»، ويحدد نوع حسابه.
- يظهر لك تنبيه في لوحة القيادة. افتح «المستخدمون»، راجع بياناته، عدّل الدور إن لزم، ثم «اعتماد».

## 5) التثبيت كتطبيق
- آيفون وآيباد (Safari): زر المشاركة ثم «إضافة إلى الصفحة الرئيسية».
- أندرويد (Chrome): القائمة ثم «تثبيت التطبيق».

## قيود الخطة المجانية في Render
- قاعدة Postgres المجانية تنتهي بعد 30 يوماً من إنشائها. للحفاظ على البيانات غيّر `plan` لقاعدة البيانات إلى خطة مدفوعة قبل انتهائها.
- الخدمة المجانية تتوقف بعد 15 دقيقة بلا استخدام، وأول فتح بعدها يتأخر قرابة دقيقة.

## الخصوصية
- رقم ملف المريض خانة اختيارية. يظهر للمشرفين ومدير النظام فقط، ولا يُكتب في سجل التدقيق.
- رقم الملف معرّف للمريض. لا تُدخل أرقاماً حقيقية قبل موافقة المنشأة (تقنية المعلومات، الأمن السيبراني، الخصوصية) على الاستضافة الخارجية.
- لا تُكتب أسماء مرضى ولا أرقام هويات ولا تشخيصات في أي خانة.

## إعدادات اختيارية (Environment)
- `TZ_OFFSET_MINUTES`: فرق التوقيت بالدقائق (السعودية 180).
- `IDLE_MINUTES`: مدة الجلسة دون استخدام (الافتراضي 20).
